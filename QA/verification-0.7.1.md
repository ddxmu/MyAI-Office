# MyAI Office 0.7.1 验收记录

环境：macOS / Apple Silicon，2026-10-16。使用独立测试窗口和自建中文 DOCX/XLSX；未修改业务原件，未覆盖 /Applications 中的用户应用。

## 字体修复与验收

- 修改前复现：Word 选择宋体/仿宋/黑体仍保留导入的 `SimSun` 东亚字体；Excel 五个字体名称保存正确，但画面仅有一种字形。
- Word 选区格式同步写入 `font_ea`；识别中文与英文别名，但仅更换拉丁字体时不覆盖原东亚字体。
- Excel 中文启动路径恢复后台字体扫描；扫描后重绘、按工作簿字体绑定实际文件，中文别名映射到兼容家族。扫描上限由 64 MiB 调整为 128 MiB，以允许 macOS 的 106,248,876 字节楷体集合，同时保留大小边界。
- 系统原字体优先，缺少时才用兼容字体；朱雀仿宋未修改、SHA-256 验证通过，完整 OFL 与来源随包分发，不安装到系统。
- `QA/verify-font-switch.py` 在两个真实编辑器中使用指针、键盘操作字体框，选择宋体、仿宋、黑体、微软雅黑、楷体。两者均得到五种不同的正文像素摘要，而非仅菜单名称不同。
- 五种字体分别保存为 DOCX/XLSX、关闭文档并重开，确认字体属性保留；Word 本地化字体在存在时可能存为等价英文家族名，例如 `Microsoft YaHei`。
- 正式 0.7.1 构建再次通过相同测试；屏幕截图、渲染、测试文档与结果保存在本机 `Build/QA/font-fix/release-native`，不上传业务文件或截图。

- Word 字体/引擎与 Excel 界面 `clippy --all-targets -D warnings` 通过；格式化、脚本语法、源码空白检查通过。
- 两个更新后的 VendorPatch 均在干净固定版本源码上通过正向检查，也在当前源码通过反向检查；保留此前所有兼容修复。补丁空白上下文由 `.gitattributes` 标记，避免被误报为源码行末空格。

## 边界

- 上述为本机五种字体与自建文件的回归，不保证每一台电脑已安装相同系统字库，也不宣称任意旧格式文件都与 WPS 完全一致。
- 兼容仿宋为上游标记 technical preview 的朱雀仿宋，并非微软 FangSong；保留用户选择的字体名以便在安装原字库的机器上使用原字体。
- 一次桌面/iCloud 测试目录的重复覆盖保存卡在系统 `rename`，停止自建测试进程后改用独立临时目录重跑通过；没有修改用户云盘设置，也没有把该环境问题声称为已修复。
